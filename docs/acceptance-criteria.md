# CampusFix --- Acceptance Criteria

## 1. Purpose

This document defines the conditions that should be met for the main
CampusFix functions to be considered complete.

## 2. Acceptance Criteria

### AC-01 - Select Room

**Requirement:** Students can select the room where a problem occurs.

**Acceptance criteria:** - A student can select a room when creating a
report. - The selected room is associated with the submitted report.

### AC-02 - Select Issue Type

**Requirement:** Students can select the type of problem.

**Acceptance criteria:** - The reporting process provides an issue type
selection. - Common issues such as broken AC, lights, fans, toilets, and
Wi-Fi can be represented. - The selected issue type is associated with
the submitted report.

### AC-03 - Submit Maintenance Report

**Requirement:** Students can submit a campus maintenance problem.

**Acceptance criteria:** - A student can provide the required reporting
information. - The report can be submitted successfully. - The submitted
report is available to the system for staff management.

### AC-04 - Staff View Reports

**Requirement:** Staff can view maintenance requests.

**Acceptance criteria:** - Staff can access submitted maintenance
requests. - The request contains the relevant room and issue
information.

### AC-05 - Organize and Prioritize Reports

**Requirement:** Staff can organize and prioritize maintenance requests.

**Acceptance criteria:** - Staff can manage the list of maintenance
requests. - Staff can identify which requests need attention or
priority.

### AC-06 - Update Report Status

**Requirement:** Staff can update a report status.

**Acceptance criteria:** - A maintenance request can have a **Reported**
status. - Staff can update the request to **Fixed**. - The updated
status is visible when the report is checked.

### AC-07 - Check Report Status

**Requirement:** Users can check the status of their report.

**Acceptance criteria:** - A submitted report has a status. - The user
can view the current status of the report. - The status reflects staff
updates.

### AC-08 - AI Chatbot Guidance

**Requirement:** The AI chatbot guides users through the platform.

**Acceptance criteria:** - Users can interact with the chatbot. - The
chatbot can provide guidance about reporting a problem. - The chatbot
can help users with status checks. - The chatbot can help users navigate
the platform.

### AC-09 - User Interface

**Requirement:** CampusFix should have an easy-to-understand user
interface.

**Acceptance criteria:** - The main reporting process is understandable
to a student. - Users can identify how to report a problem without
needing complicated instructions. - The main functions are presented
clearly.

## 3. Overall Project Acceptance

CampusFix can be considered ready for the documented core scope when
students can report campus maintenance problems, staff can manage and
update those reports, users can check report status, and the AI chatbot
provides the described guidance.
