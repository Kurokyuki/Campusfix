# CampusFix --- Requirements Specification

## 1. Introduction

CampusFix is a website for reporting and managing campus maintenance
problems.

The system is intended to make it easier for students to report problems
and for university staff to manage maintenance requests.

## 2. User Types

### 2.1 Students

Students use CampusFix to report problems they find on campus and check
the status of their reports.

### 2.2 University Staff

University staff use CampusFix to view, organize, prioritize, and manage
maintenance requests.

### 2.3 Lecturers

The project material identifies lecturers as a potential user group and
describes the possibility of choosing classrooms based on reported room
issues. This function should be confirmed by the project group before
implementation.

## 3. Functional Requirements

### FR-01 - Select Room

The system will allow a student to select the room where a campus
problem has occurred.

### FR-02 - Select Issue Type

The system will allow a student to select the type of facility problem
being reported.

Examples include: - Air conditioner - Light - Fan - Toilet - Wi-Fi -
Other campus facilities

### FR-03 - Submit Maintenance Report

The system will allow students to submit a maintenance report after
selecting the relevant room and issue type.

### FR-04 - View Maintenance Requests

The system will allow university staff to view submitted maintenance
requests.

### FR-05 - Organize and Prioritize Requests

The system will allow university staff to organize and prioritize
maintenance requests.

### FR-06 - Update Request Status

The system will allow university staff to update a maintenance request
from **Reported** to **Fixed**.

### FR-07 - Check Report Status

The system shall allow users to check the status of a maintenance
report.

### FR-08 - AI Guidance

The system will provide an AI chatbot that guides users through
reporting, status checks, and platform navigation.

## 4. Non-Functional Requirements

The project material specifically describes the platform as having an
easy-to-understand user interface.

### NFR-01 - Usability

The website should have an easy-to-understand user interface.

### NFR-02 - Simplicity

The reporting process should be simple for students to use.

## 5. Potential Additional Features

The project presentation also discusses these ideas:

-   A digital map showing course locations and reported problems.
-   Lecturer classroom selection based on room issues.
-   An AI chatbot answering questions about classrooms, schedules,
    campus services, and university rules.
-   A freshman-focused AI assistant.

These were presented as ideas during the ideation stage. The final
CampusFix concept focuses on the maintenance reporting system and its AI
chatbot, so the additional features should only be treated as
requirements if the group decides to include them.

## 6. Constraints and Open Questions

The provided project material does not specify: - Programming language -
Database management system - Authentication method - Hosting platform -
Exact user permissions - Exact report fields beyond room and issue
type - Detailed AI implementation - Project deadline

These technical details should be decided by the project group.
